# 双电机 + 前万向轮：蓝牙调试首版

这版用于先验证底盘，再用蓝牙手动驾驶跑赛图。前万向轮没有驱动和舵机，转向由后面两个驱动轮的速度差产生。没有接入图像，也没有自动巡线；赛题 PDF 第2页要求正式比赛自主行驶、禁止遥控，因此这版用于练习调试。

## 1. 工程与资料依据

- 主控：STM32F407VET6，沿用 NEUQ HAL 库、5ms 控制周期和 `Car_PID` 速度环。
- 引脚依据：`22届校赛主板原理图参考 (1) (1).pdf`、`22届校赛驱动板原理图参考 (1).pdf`。
- 核心板外围依据：`V2(1).pdf`，Flash CS 为 PB0；程序启动时将其置高，因为 PA5/6/7 已用于电机及编码器。
- 蓝牙依据：`JDY-31-K1234.PDF`，经典蓝牙 SPP，默认串口9600、配对密码1234。支持 Windows/Android；本工具运行在 Windows 电脑上。
- 工程仅运行当前双轮蓝牙程序；已移除单电机考核入口、旧协议和任务选择配置。硬件参数统一在 `CODE/Car_Config.h`。

## 2. 接线

**此处约定：从车后向前看，左轮用驱动通道1，右轮用通道2。** 原单电机台架曾把动力线接通道2、编码器接通道1；这次必须把同一电机的动力与反馈配成同一通道，不能沿用那种混接。

| 功能 | MCU 引脚 | 定时器 / 接口 | 主板 H11 对应驱动板 H1 |
|---|---|---|---|
| 左轮方向 | PC7 | GPIO，DIR_1_IN | 1 |
| 左轮 PWM | PC6 | **TIM8_CH1**，PWM_1_IN | 7 |
| 左轮编码器 | PB6 / PB7 | TIM4 CH1 / CH2 | 5 / 3 |
| 右轮方向 | PA5 | GPIO，DIR_2_IN | 2 |
| 右轮 PWM | PA2 | TIM2_CH3，PWM_2_IN | 10 |
| 右轮编码器 | PA6 / PA7 | TIM3 CH1 / CH2 | 6 / 4 |
| 信号地 | GND | 主板与驱动板共地 | 8 / 9 |
| 蓝牙 RXD | PC10 → RXD | UART4 TX，库中叫 UART_3 | 主板串口座2 |
| 蓝牙 TXD | TXD → PC11 | UART4 RX，库中叫 UART_3 | 主板串口座3 |
| 蓝牙 GND | GND | 共地 | 主板串口座1 |

左电机插驱动 U9（通道1），右电机插 U8（通道2），按参考原理图标签确认实板丝印。IDC 插头方向按1脚标记核对。驱动板 SW1 要使能 nSLEEP，否则不会转。

**PC6 必须使用 TIM8，不能改成 TIM3 PWM**，因为右轮编码器已占用 TIM3。不要同时初始化摄像头、SPI1 Flash 或占用这些管脚的外设。

JDY-31 带底板版本 VCC 按手册接3.6–6V（建议5V），裸模块 VCC 是1.8–3.6V；先确认模块版本。主板三针串口座没有电源脚，VCC 需要单独接。UART信号使用3.3V TTL，TX/RX交叉连接。

## 3. 编译与烧录

1. 打开 `MDK-ARM/NEUQ_STM32F407VET6_Opensource_Library.uvprojx`，使用现有 ARM Compiler 5，Rebuild。
2. 已在工程中加入 `Car_Core.c`、`Car_Hardware.c`，无需手动加文件。
3. 烧录输出：`MDK-ARM/NEUQ_STM32F407VET6_Opensource_Library/NEUQ_STM32F407VET6_Opensource_Library.hex`。也可以用 Keil Download 经 ST-Link/SWD 下载。
4. 上电保持停车，必须收到合法使能，再收到轮速指令才运动。复位和掉电后不会恢复原来的运动。

本机验证脚本（需要 Python、clang，以及所示路径的 Keil）：

```powershell
powershell -ExecutionPolicy Bypass -File Tools/check_car.ps1
```

## 4. 蓝牙与电脑工具

1. Windows 设置里配对 `JDY-31-SPP`，默认 PIN `1234`，找到其**出站 SPP COM口**。电脑须支持经典蓝牙 SPP。
2. 安装依赖并启动：

```powershell
python -m pip install -r Tools/requirements-car.txt
python Tools/car_host.py
# 可选：预选串口，记录16通道回传
python Tools/car_host.py --port COM8 --log car_run.csv
```

3. 选对 COM，默认波特率9600，点击连接。收到停止回传后点击“使能”。第一次保持默认60rpm，车轮必须架空。
4. 按住 W/↑前进、S/↓后退、A/←原地左转、D/→原地右转；W+A / W+D 为向前弧线转弯。按钮也可以按住操作。松开全部方向键发送双轮零速并制动，保持使能。
5. 空格或红色按钮停止并取消使能，连接保持时会间隔150ms再重发两次STOP，以防第一条落入通信残帧；重发期间不能使能。窗口失焦也会重复停止；关闭、断开连接会尽力发送STOP，链路不可用时由500ms超时停车。故障或失焦后须重新点击使能。
6. 速度框或 PID 输入框编辑时不接受方向快捷键；点方向按钮或使能按钮后再使用键盘。若回传中断超过350ms，电脑端停止并取消使能；车端500ms收不到有效续租指令时故障停车。

蓝牙模块和MCU的串口波特率必须一致。若模块以前已设115200，将 `CAR_UART_BAUD` 改为 `UART_BAUD_115200` 并重新编译，GUI也选115200。Windows虚拟COM的波特率选择通常不会修改蓝牙模块自身UART配置。

需要修改模块时，先断开蓝牙，使用 USB-TTL 直接连接模块，按当前波特率发送 AT 指令并附加 `\r\n`：`AT+BAUD` 查询；`AT+BAUD4` 设9600，`AT+BAUD8` 设115200；可用 `AT+ENLOG0` 关闭模块状态文本。不要向正在工作的车载控制串口发送AT指令来改模块。

## 5. 第一次架空校准（左右轮分别测）

`CODE/Car_Config.h` 集中保存首版配置。默认电机参数沿用旧台架：11线、四倍频、减速比10，输出轴每转440计数；新电机若不同，必须修改 `CAR_ENCODER_CPR`。

用户已确认使用JGB37-520霍尔编码器电机、输出轴空载约1000rpm。440计数仍只是初始台架假设，并未因型号确认而成为实测值；需核对编码器PPR和减速比，或直接测量输出轴一圈计数。180rpm和35%PWM是低速调试限幅，不是电机额定能力。

1. 先检查通道归属，确认左轮动力与左轮反馈均在通道1，右轮均在通道2。
2. 低速只测试左轮，然后只测试右轮。GUI可用 W+A / W+D 观察，单轮精确测试可用下述HEX速度指令并持续心跳。驱动正方向应让轮子带动车体向前；若反了，翻转对应 `CAR_*_FORWARD_HIGH`。
3. 正向驱动时回传实测 rpm 必须为正。若为负，翻转对应 `CAR_*_ENCODER_INVERT`。两个宏默认都是1，仅为初始假设，**不是已实测结论**。改变电机正方向后须再次核对编码器符号。
4. 检查制动、空格停止、断开蓝牙后约500ms停车。故障会让两轮同时停下，不会恢复后自动继续。
5. 左右分别测试通过，再落地以40–80rpm试直线和小弯，逐步提高速度。万向轮换向会摆正，应低速观察，不要一开始高速原地掉头。

如果需要经常单轮调试，可以用串口助手发命令。电脑工具也能离线生成HEX：

```powershell
python Tools/car_host.py --hex arm
python Tools/car_host.py --hex wheels 60 0
python Tools/car_host.py --hex wheels 0 60
python Tools/car_host.py --hex heartbeat
python Tools/car_host.py --hex stop
```

串口助手需每100ms周期发送合法心跳或轮速；仅发送一次轮速会在500ms后停车。上位机工具自动重复轮速，无需手工心跳。同一COM只能由一个程序打开。

## 6. 调参、保护与回传

- 初始速度环：左右各自 `Kp=2, Ki=0.12, Kd=0`，Ki/Kd保留5ms离散参数语义；控制器按实际dt归一化，并新增测量微分滤波、前馈配置和数值检查，详见[速度控制升级](Speed_Control_Upgrade.md)。
- 先按停止，等停止回传后，在对应轮的输入框修改PID并点击写入。对照“实际PID”确认回传生效，两个轮独立调整；只保存于RAM。
- 转速限幅±180rpm，PWM限幅±3500/10000（35%）。双轮共享五次曲线进度，加速度≤200rpm/s、加加速度≤800rpm/s²；转向目标改变时平滑结束旧参考的加速趋势。双轮零速指令立即清PID、清曲线、置零输出；机械停止仍需要实际制动时间。
- 输出换向前先将PWM置零至少一个控制周期。
- 链路500ms无有效轮速/心跳，锁定故障1；故障后先STOP，再ARM，目标从零开始。错误CRC、残帧、PID指令不会续租。
- 参考转速≥40rpm、PWM≥15%而测得转速<10rpm持续1.5s，故障2（堵转或无反馈）。目标/输出与实测反向、接近PWM限幅且转速>100rpm、没有明显减速持续1s，故障3。保护有阈值，仍需正确接线。
- 串口硬件错误或RX缓冲溢出会清缓冲并锁定故障4。
- 每100ms一帧 VOFA JustFloat：16个小端float + `00 00 80 7F`，68字节，680字节/秒，适合9600 baud 8N1。

| 通道 | 内容 |
|---|---|
| I0 / I1 | 状态0停止/1运行/2故障；故障码0正常/1通信/2堵转/3方向/4串口/5控制周期/6控制器数值 |
| I2 / I3 | 左轮斜坡后目标/实测 rpm |
| I4 / I5 | 右轮斜坡后目标/实测 rpm |
| I6 / I7 | 左右PID请求PWM百分比（换向等待周期实际输出为0） |
| I8 / I9 | 最近命令结果0成功/1状态拒绝/2数值错误/3帧错误；CRC正确的命令帧数 |
| I10–I12 | 左轮实际 Kp / Ki / Kd |
| I13–I15 | 右轮实际 Kp / Ki / Kd |

协议：`C3 3C CMD LEN DATA CRC8`，CRC8多项式0x07，初值0，覆盖CMD、LEN和DATA。CMD1 ARM无数据；2 STOP无数据；3 WHEELS长度4（左右各大端带符号int16 rpm）；4 PID长度7（轮0左/1右，随后大端uint16 Kp/Ki/Kd各乘100）；5 HEARTBEAT无数据。帧内间隔超过100ms丢弃残帧。不兼容原第三题的 `AA ... 55`。

## 7. 实车跑图顺序

先完成架空单轮方向和反馈检查，再在空地测试直行、弧线、急停和断链停车，最后低速手动跑赛图。根据45cm赛道的实际弯道半径调整速度与转向；本版不推测轮距、轮径和路线，也不按55.061m赛道长度虚构自动路径。

代码已做逻辑测试和Keil编译验证。未连接车辆、未烧录、未测实际PID/轮速/停车距离；不能据此声称已经实车完成一圈。
