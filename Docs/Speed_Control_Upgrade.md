# 速度控制升级实施契约

目标：提升当前轮速跟踪和转向指令平顺性；不承诺尚未测量的高速过弯精度，不把速度环当作航向/路径闭环。本次改动集中在现有PID、目标生成与控制时基，串口和视觉协议保持兼容。

状态：本页列出的速度控制升级已落地；最后列出的航向、视觉和高速轨迹控制仍未实现。

## 实施

1. PID使用实际dt并保留既有蓝牙Ki/Kd的5ms离散参数含义；比例、积分、微分量分开，微分仅对测量且一阶滤波，条件积分抗饱和，非法输入/参数使输出零并给出错误状态。提供kS/kV/kA前馈配置入口，默认全0，未经标定不得依据空载1000rpm猜测系数。
2. 以共同的前进/差速目标生成左右参考，限制每轮加速度与加加速度（jerk），支持目标反向，紧急停止绕过缓升并清历史；普通过渡允许短时制动超调，但不能突破速度/加速度边界。不通过任意提高RPM/PWM上限声称性能提高。
3. 控制读取独立运行的TIM5微秒计时，采样到控制之间使用真实dt，失效/过长周期故障停车；通信、堵转和方向保护按实际微秒累计，时间回绕用无符号差值。由时间常数计算测速滤波。
4. 单独测试PID噪声抑制、无设定值微分冲击、积分抗饱和、时间步长一致性、非法值、前馈；测试参考加速度/jerk界限、正反向、双轮转向过渡、STOP；保持原通信与视觉回归，Keil全量编译并审查。

验收只覆盖软件边界与仿真响应，不等于实车高速精度验证。MPU6050航向闭环、曲率/侧向加速度限速、轮径/轮距/CPR标定以及视觉路径控制仍是后续任务；本次不生成空实现来声称已完成。

## 已实现与使用

- `Car_PID.c/.h`：独立的P/I/D/前馈项、可配置设定值权重beta（默认1）、对测量值微分和20ms默认低通、条件积分抗饱和、有限值/周期检查。蓝牙Ki/Kd保留5ms离散参数语义，按实际dt归一化，旧GUI与16通道回传保持兼容。
- `Car_Reference.c/.h`：左右轮共享进度的五次曲线，默认加速度上限200rpm/s、加加速度上限800rpm/s²。连续改目标时先以受限jerk结束当前参考加速度，再生成下一段；从静止到固定双轮目标时保持参考轮速比例。它不保证实际轮速总能跟上，也不是航向闭环。
- `Car_Hardware.c`：独占TIM5作1MHz自由运行时间基，不占引脚、不启用中断；控制周期通过无符号差值处理回绕。实际间隔1..15ms可更新，超界故障停车（代码5）。这些期限是初始软件策略，需在实物调度预算下验证。
- `Car_Core.c`：测速滤波、PID、斜坡和通信/堵转/方向期限使用实际采样间隔；数值或控制器故障停车（代码6）。保留首次故障原因。
- STOP、故障、蓝牙双轮零速指令直接清除参考曲线、加速度和PID历史，输出归零，绕过平顺性限制；机械停车距离仍须实测。

`CAR_PID_D_TAU_S`、`CAR_PID_SETPOINT_WEIGHT`、`CAR_ACCEL_LIMIT_RPM_S`和`CAR_JERK_LIMIT_RPM_S2`集中在Car_Config.h。前馈`CAR_FF_KS/KV/KA`默认全0，只能根据本车数据标定后启用；单位为PWM计数、rpm、rpm/s，未做电池电压补偿，不能直接照抄以伏特为单位的系数。内部接口`Car_Pid_configure`仅应在停车状态调用。

先架空标定CPR/方向，再以PI为主调整速度环；D项只在记录证明有收益时小量加入。当前RPM/PWM上限仍为180rpm/35%，没有自动提高。高速过弯还需测量轮径轮距和抓地极限，实施由曲率决定的速度规划，以及IMU/视觉外环；不能只增加PID增益。

## 验证

新增控制器测试覆盖：dt变化下积分一致性、无设定值微分冲击、微分噪声滤波、饱和不积累、前馈公式、非法数值、双轮参考比例、变目标和紧停。另用20000步确定性输入覆盖1..15ms变dt、连续改目标下的参考速度/加速度/jerk边界。原通信/停车及视觉回归仍运行。
